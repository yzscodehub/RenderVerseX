# RVX-NG · 北极星设计宪章

**日期**：2026-06-26  
**状态**：北极星设计原则 · v1.0 框架定稿

本文定义 RVX-NG 的设计阶段边界：先建立一个基于现代游戏引擎最佳实践、完整且可验证的目标架构，再单独设计当前引擎向该目标演进的实施方案。

## 1. 定位

RVX-NG 是 RenderVerseX 的下一代目标架构，不是当前实现的补丁计划，也不是迁移排期。

目标架构应回答：

- 一个现代实时渲染/游戏运行时引擎应该如何分层。
- 哪些能力属于首期主线，哪些属于高端档或研究档。
- 每个模块的职责、接口、不变量、数据布局、线程模型、失败语义、性能目标、测试门禁是什么。
- 各模块如何通过单向依赖、快照、句柄、反射、RenderGraph、JobSystem 等机制连接。

目标架构暂不回答：

- 当前代码哪些保留、哪些重写、哪些桥接。
- 具体排期、人员、分支策略、阶段性提交计划。
- 旧模块兼容层设计。

这些内容在北极星设计完成后进入“实施与迁移方案”。

## 2. 设计输入

北极星设计的主要输入是：

- 现代游戏引擎最佳实践：混合 authoring + 数据导向热路径、task graph、显式 RHI、RenderGraph、GpuScene、GPU-driven rendering、asset cook/DDC、World Partition、Editor 同运行时、可测性门禁。
- RenderVerseX 的长期定位：跨平台、多后端、高质量实时渲染、可生产化工具链。
- 工程可验证性：所有能力必须可测试、可降级、可观测。
- 已知技术约束：跨平台 GPU 差异、浮点确定性边界、主机 SDK 差异、shader/PSO hitch、显存/IO 预算。

当前实现可作为经验教训来源，但不得限制目标架构本身。

## 3. 设计输出

北极星阶段输出以下文档：

- Tier-0 架构总纲。
- 每个模块的 Tier-1 详细设计。
- 跨切面设计：帧时序、内存预算、确定性、测试、构建系统。
- 最佳实践校准表。
- 设计完成度矩阵。
- Spike 注册表。
- 全局依赖 DAG 与能力分级表。

不输出实施方案、迁移计划、当前代码改造清单。

## 4. 文档纯度规则

北极星目标设计文档中应避免：

- “替代当前 X”“修现有 Y”“复活死代码”等实现迁移措辞。
- 以当前模块形状为理由降低目标架构质量。
- 把临时兼容层写成长期架构。
- 把未验证技术写成主线依赖。

允许保留：

- 技术风险与工程教训。
- 明确的 non-goals。
- 高风险项的 fallback 和 spike。
- “后续迁移评估另起文档”的提示。

## 5. 完成定义

一个模块达到“可评审”必须具备：

- 目标与范围。
- 需求与约束。
- 公共接口面。
- 不变量。
- 数据结构与内存布局。
- 核心算法。
- 线程与内存模型。
- 错误与失败语义。
- 性能目标。
- 测试计划。
- 开放问题 / Spike。
- 依赖与被依赖。

一个模块达到“可进入实施方案设计”还必须具备：

- 关键 spike 已关闭。
- 接口与数据边界稳定。
- 能力分级与 fallback 完整。
- 验收标准可自动测试。
- 与跨切面设计无冲突。

## 6. 决策原则

1. **主线可出货**：首期主线必须使用已验证技术或低风险工程路线。
2. **高端可叠加**：研究级能力只能作为可关闭的叠加档。
3. **能力诚实**：caps、stats、test、fallback 必须反映真实行为。
4. **数据热路径优先**：海量/热域数据导向，authoring 友好性通过门面解决。
5. **边界明确**：Feature 不碰 RHI，Render 不读 gameplay 类型，RHI 不吸收高层语义。
6. **可测性前置**：没有测试入口的能力不进入架构主线。
7. **预算先行**：CPU、GPU、显存、IO、音频、脚本都必须有预算模型。
